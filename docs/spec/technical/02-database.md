# 02 · Database

PostgreSQL 16. One database `homeflow`, one schema `public`. The entity shapes come from [`../foundation/data-model.md`](../foundation/data-model.md) and each role spec's "Entities owned"; this file fixes the mechanics every table shares and gives full DDL for the kernel tables the foundation only describes.

---

## 1. Roles and grants

```sql
CREATE ROLE homeflow_owner LOGIN;            -- runs Alembic; owns every object
CREATE ROLE homeflow_app   LOGIN NOBYPASSRLS;-- the API; RLS applies to it
GRANT USAGE ON SCHEMA public TO homeflow_app;
ALTER DEFAULT PRIVILEGES FOR ROLE homeflow_owner IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE ON TABLES TO homeflow_app;   -- note: no DELETE by default
ALTER DEFAULT PRIVILEGES FOR ROLE homeflow_owner IN SCHEMA public
  GRANT USAGE ON SEQUENCES TO homeflow_app;
-- append-only tables: not even UPDATE
REVOKE UPDATE, DELETE ON event, service_history, execution_record, forecast_snapshot FROM homeflow_app;
-- the few tables that may be hard-deleted (non-material): 
GRANT DELETE ON session, otp_challenge, job, unit_requirement_match, opportunity_need TO homeflow_app;
```

`DELETE` is a grant, not a habit: material history is never deleted ([`../foundation/data-model.md`](../foundation/data-model.md) §5). Locally the same two roles exist in the compose Postgres so a missing grant fails on the laptop first.

## 2. Conventions

| Rule | Value |
|---|---|
| Table names | `snake_case`, singular: `booking`, `unit_change_gate`, `booking_applicant`. |
| Primary key | `id uuid PRIMARY KEY DEFAULT uuid_generate_v7()`. |
| Foreign keys | Always declared, `ON DELETE RESTRICT` (nothing material cascades). Named `fk_<table>_<column>`. |
| Enums | Postgres `CHECK (col IN (...))` constraints, not `CREATE TYPE` (cheaper to evolve). Values `SCREAMING_SNAKE` only where the foundation uses them (`OPEN`…`HARD_CLOSED`); otherwise `snake_case`. |
| Money | `numeric(14,2)`. Percentages `numeric(5,2)`. |
| JSON | `jsonb`; every jsonb column has a Pydantic model that is the only writer. |
| Timestamps | `timestamptz`. `created_at DEFAULT now()`, `updated_at` maintained by trigger `set_updated_at()`. |
| Derived columns | Suffix `_computed_at` beside any cached derivation (`completeness_score`, `sale_status`, scores). |
| Effective dating | `effective_from date NOT NULL, effective_to date NULL`; an `EXCLUDE USING gist` prevents overlap where uniqueness matters (team assignment). |
| Soft state | `status` column with the spec's states; no `is_deleted`. |
| Optimistic concurrency | `version int NOT NULL DEFAULT 1` on `booking`, `change_request`, `generated_document`, `action`; `UPDATE … WHERE version = :v` → 409 on mismatch. |

**Standard block** on every project-partitioned table (everything except `project`, `customer`, `user`, `role`, `permission`, config tables, kernel tables that say otherwise):

```sql
id          uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
project_id  uuid NOT NULL REFERENCES project(id),      -- derived on write, re-validated by trigger
created_at  timestamptz NOT NULL DEFAULT now(),
updated_at  timestamptz NOT NULL DEFAULT now()
```

Trigger `enforce_project_id()` on tables that hang off `unit` or `booking`: on INSERT/UPDATE, sets `project_id` from the parent and rejects a mismatch. The API never sends `project_id` for those rows.

`uuid_generate_v7()` is a 12-line plpgsql function in migration 0001 (timestamp-prefixed `gen_random_uuid`), so ids sort by time and no extension is needed beyond `pgcrypto` and `pg_trgm`.

## 3. Row-level security

Enabled on every project-partitioned table. The GUCs are set by `kernel/db.py::tx()` per transaction (03 §6).

```sql
ALTER TABLE booking ENABLE ROW LEVEL SECURITY;
ALTER TABLE booking FORCE ROW LEVEL SECURITY;

-- staff: project membership, or an all-projects role
CREATE POLICY staff_project ON booking
  USING (
    current_setting('app.realm', true) = 'staff'
    AND ( current_setting('app.all_projects', true) = 'true'
          OR project_id = ANY (string_to_array(current_setting('app.project_ids', true), ',')::uuid[]) )
  );

-- customer: only rows reachable from their own bookings (defined only on customer-readable tables)
CREATE POLICY customer_own ON booking
  USING (
    current_setting('app.realm', true) = 'customer'
    AND id IN (SELECT booking_id FROM booking_applicant
               WHERE customer_id = current_setting('app.customer_id', true)::uuid)
  );
```

- Policies are generated by one Alembic helper `rls(table, customer_via=None)` so every table gets the identical staff policy; `customer_via` names the join path for the customer policy (`booking_id`, `unit_id` via booking, or none).
- Customer-readable tables: `booking`, `unit`, `demand`, `receipt`, `generated_document`, `commitment` (visibility = customer_facing), `communication` (customer_facing), `change_request`, `home_passport_item`, `handover_record`, `warranty_case`, `customer_update`. Everything else has no customer policy and is therefore invisible in the customer realm.
- **Field-level** hiding (TRUE_RISK, internal notes, vendor cost) is not RLS; it is the response model + `rbac_redact` (03 §8) and the H10 projection (08 §5). RLS answers "which rows", never "which columns".
- `customer` (the master row) is not project-partitioned; its policy is `staff` OR `id = app.customer_id`.
- Config tables (`change_category`, `sla_policy`, templates…) are readable by all staff; writable only through `modules/admin`.

A test in `tests/rls/` connects as `homeflow_app`, sets the GUCs for a user on project A, and asserts zero rows from project B on every partitioned table (enumerated from `information_schema`).

## 4. Kernel tables (full DDL)

### 4.1 Identity

```sql
CREATE TABLE "user" (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  email citext UNIQUE NOT NULL, full_name text NOT NULL, phone text,
  is_active boolean NOT NULL DEFAULT true,
  google_sub text UNIQUE,                       -- filled on first successful sign-in
  last_login_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now());

CREATE TABLE role (id text PRIMARY KEY, name text NOT NULL, all_projects boolean NOT NULL DEFAULT false);
-- ids = v1 canonical roles: super_admin, management, sales, crm, accounts, banking, legal, registration,
--       site_engineer (→ project-site), qa, facility (→ post-handover), design, procurement

CREATE TABLE user_role_assignment (
  user_id uuid REFERENCES "user"(id), role_id text REFERENCES role(id), PRIMARY KEY (user_id, role_id));

CREATE TABLE permission (                        -- seeded from v1 rbac_matrix.py; editable in Policy Studio
  role_id text REFERENCES role(id), module text, level text NOT NULL
    CHECK (level IN ('none','read_status_only','read_limited','read','write','admin')),
  modifiers jsonb NOT NULL DEFAULT '{}',          -- { hidden_fields: [...], masked_fields: [...], own_only: bool }
  PRIMARY KEY (role_id, module));

CREATE TABLE session (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  token_hash bytea UNIQUE NOT NULL,               -- sha256(token); the token itself is only in the cookie
  realm text NOT NULL CHECK (realm IN ('staff','customer')),
  user_id uuid REFERENCES "user"(id), customer_id uuid REFERENCES customer(id),
  CHECK ((realm='staff' AND user_id IS NOT NULL) OR (realm='customer' AND customer_id IS NOT NULL)),
  created_at timestamptz NOT NULL DEFAULT now(), last_seen_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL, ip inet, user_agent text, revoked_at timestamptz);
CREATE INDEX ON session (user_id) WHERE revoked_at IS NULL;

CREATE TABLE otp_challenge (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  phone text NOT NULL, customer_id uuid NOT NULL REFERENCES customer(id),
  code_hash bytea NOT NULL, expires_at timestamptz NOT NULL, attempts int NOT NULL DEFAULT 0,
  consumed_at timestamptz, created_at timestamptz NOT NULL DEFAULT now());
CREATE INDEX ON otp_challenge (phone, created_at);
```

### 4.2 Event log

```sql
CREATE TABLE event (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  event_type text NOT NULL,                       -- must exist in kernel/events/catalogue.py (checked in app)
  occurred_at timestamptz NOT NULL, recorded_at timestamptz NOT NULL DEFAULT now(),
  project_id uuid REFERENCES project(id),         -- nullable only for portfolio/config events
  actor jsonb NOT NULL,                           -- { type, id, name }
  subject jsonb NOT NULL,                         -- { unit_id?, booking_id?, customer_id?, ... }
  payload jsonb NOT NULL DEFAULT '{}',
  previous_state jsonb, new_state jsonb, reason_code text,
  correlation_id uuid, source jsonb);
CREATE INDEX ON event (project_id, recorded_at DESC);
CREATE INDEX ON event (correlation_id);
CREATE INDEX ON event USING gin (subject jsonb_path_ops);
REVOKE UPDATE, DELETE ON event FROM homeflow_app;
```

Not partitioned: at 1–2 M rows/year a single indexed table is fine for years. Partition by month when it passes ~50 M rows (a one-migration change; the foundation's storage note is updated to say so).

### 4.3 Jobs

```sql
CREATE TABLE job (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  kind text NOT NULL, args jsonb NOT NULL DEFAULT '{}',
  status text NOT NULL DEFAULT 'queued' CHECK (status IN ('queued','running','done','failed','dead')),
  run_at timestamptz NOT NULL DEFAULT now(),
  attempts int NOT NULL DEFAULT 0, max_attempts int NOT NULL DEFAULT 5,
  last_error text, dedupe_key text, correlation_id uuid, project_id uuid,
  created_at timestamptz NOT NULL DEFAULT now(), started_at timestamptz, finished_at timestamptz);
CREATE INDEX ON job (run_at) WHERE status = 'queued';
CREATE UNIQUE INDEX ON job (dedupe_key) WHERE status IN ('queued','running');

CREATE TABLE schedule (
  kind text PRIMARY KEY, args jsonb NOT NULL DEFAULT '{}',
  every_seconds int, daily_at time,               -- exactly one of the two
  CHECK ((every_seconds IS NULL) <> (daily_at IS NULL)),
  enabled boolean NOT NULL DEFAULT true, last_run_at timestamptz, next_run_at timestamptz NOT NULL);
```

`job` rows are pruned by a `job.prune` schedule (done > 7 days, dead > 90 days) — the only hard delete of kernel data, and it is not material history (the events they produced remain).

### 4.4 Files

```sql
CREATE TABLE file_object (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(),
  project_id uuid REFERENCES project(id),
  entity_type text NOT NULL, entity_id uuid NOT NULL,   -- what it is attached to
  s3_key text UNIQUE NOT NULL,                          -- {project_id}/{entity_type}/{entity_id}/{id}
  filename text NOT NULL, content_type text NOT NULL, size_bytes bigint, sha256 bytea,
  visibility text NOT NULL DEFAULT 'internal' CHECK (visibility IN ('internal','customer_facing')),
  status text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','ready')),   -- ready after confirm
  uploaded_by jsonb NOT NULL, created_at timestamptz NOT NULL DEFAULT now());
CREATE INDEX ON file_object (entity_type, entity_id);
```

### 4.5 Action, SLA, escalation

```sql
CREATE TABLE sla_policy (                         -- config
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(), project_id uuid REFERENCES project(id),   -- null = Pranava default
  code text NOT NULL, action_type text, duration_hours int NOT NULL, working_hours_only boolean NOT NULL DEFAULT true,
  warn_at_pct int NOT NULL DEFAULT 80, repeat_breach_threshold int NOT NULL DEFAULT 2,
  pause_reasons jsonb NOT NULL DEFAULT '[]', effective_from date NOT NULL, effective_to date,
  UNIQUE (project_id, code, effective_from));

CREATE TABLE action (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(), project_id uuid NOT NULL REFERENCES project(id),
  type text NOT NULL CHECK (type IN ('task','approval','document','payment','snag','commitment','customer_contact','inspection','escalation','ai_recommendation')),
  title text NOT NULL, description text,
  related jsonb NOT NULL,                         -- { unit_id?, booking_id?, customer_id?, record_type?, record_id? }
  owner_id uuid NOT NULL REFERENCES "user"(id), owner_department text NOT NULL, backup_owner_id uuid REFERENCES "user"(id),
  reassignment_history jsonb NOT NULL DEFAULT '[]',
  priority text NOT NULL DEFAULT 'normal', severity jsonb NOT NULL DEFAULT '{}',
  sla_policy_id uuid REFERENCES sla_policy(id), sla_due_at timestamptz, sla_paused_at timestamptz, sla_pause_reason text,
  sla_level int NOT NULL DEFAULT 0 CHECK (sla_level BETWEEN 0 AND 4), breach_count int NOT NULL DEFAULT 0,
  plan_date date, dependencies jsonb NOT NULL DEFAULT '{}', business_impact jsonb NOT NULL DEFAULT '{}',
  evidence_required jsonb NOT NULL DEFAULT '[]', evidence_ids uuid[] NOT NULL DEFAULT '{}',
  state text NOT NULL DEFAULT 'new' CHECK (state IN ('new','in_progress','waiting_internal','waiting_customer','blocked','ready_for_approval','closed','cancelled')),
  why_now text, rank_score numeric(8,3), rank_computed_at timestamptz,
  source text NOT NULL CHECK (source IN ('manual','workflow','rule','ai')), source_ref jsonb,
  version int NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now(), closed_at timestamptz);
CREATE INDEX ON action (owner_id, state) WHERE state NOT IN ('closed','cancelled');
CREATE INDEX ON action (project_id, state, sla_due_at);
CREATE INDEX ON action USING gin (related jsonb_path_ops);

CREATE TABLE escalation (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v7(), project_id uuid NOT NULL REFERENCES project(id),
  source_action_id uuid NOT NULL REFERENCES action(id),
  category text NOT NULL CHECK (category IN ('customer','cash','handover','reputation','margin')),
  tier text NOT NULL CHECK (tier IN ('L2','L3','L4')),
  owner_id uuid NOT NULL REFERENCES "user"(id), backup_owner_id uuid REFERENCES "user"(id),
  decision_pack jsonb NOT NULL, recovery_plan jsonb,
  status text NOT NULL DEFAULT 'created' CHECK (status IN ('created','upgraded','recovery_planned','closed')),
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now());
```

journey_template(id, code, name, product_type, status)

## 7. Migrations and seeds

- Alembic, one linear head, forward-only. Migration files are hand-written SQL via `op.execute` for DDL, policies and grants (autogenerate is used only to draft). Each migration ends with the `rls()` helper for any new partitioned table — a CI test fails if a partitioned table has RLS disabled.
- `0001_kernel` (functions, roles, identity, event, job, file_object), `0002_core` (project, hierarchy, unit, customer, booking, applicant, team), `0003_twins` (progress, gates, spec, as-built, QA, snag, passport), `0004_action_journey`, `0005_money`, `0006_legal`, `0007_handover_post`, `0008_crm_customer`, `0009_management_config`. Later changes are one migration each, reviewed ("Ask first").
- Migrations run at container start: `alembic upgrade head` under `SELECT pg_advisory_lock(42)` so two tasks starting together do not race.
- **Config seed** (`seeds/config/`, always, idempotent by natural key): roles, permission matrix from v1, component taxonomy, change categories + gate rules for villa and apartment, Pranava Standard Journey v1, SLA policies, message templates, document templates, customer stage map, working calendar.
- **Demo seed** (`seeds/demo/`, `HOMEFLOW_DEMO=1`): East Crest with ~40 units at varied progress, ~25 bookings across stages, demands/receipts, snags, documents — the data the Playwright screenshots run against. Uses the real handshake functions so events and Actions are produced, never inserted raw.
