## Item A — Identity and sessions (TASKS Vivek 5 · technical 03)

### Why

Technical 03 replaces v1's whole identity stack: Google OIDC server-side for staff, an OTP to the booking mobile for customers, one `session` table, no passwords anywhere. v1 authenticated with bcrypt + a self-minted JWT and an Emergent-hosted OAuth broker (`auth.emergentagent.com`) — a third party in the trust path, a token this app cannot revoke, and a password hash to leak. `v1-reuse.md` §4.6 names the exact code to delete. Authorisation splits into the three layers of 03: the RBAC matrix decides *what*, RLS decides *which rows*, `permission.modifiers` decides *which fields*.

### Benefit

An operator can be provisioned by an admin and sign in with their Pranava Workspace account; nobody can self-register (`403 NOT_PROVISIONED`), nobody has a password to phish, and a leaked cookie can be revoked from the database — the JWT could not be. Deactivating a user kills their live sessions in the same transaction. Customers reach the portal with a code to the mobile already on their booking; a wrong number gets the same `{sent: true}` as a right one, so the endpoint cannot be used to test whether someone is a Pranava customer. Every non-GET is CSRF-protected by one header, everywhere, with no per-route opt-in to forget. And the permission matrix stopped being Python: 585 rows Policy Studio will edit.

### Code difference

**v1 minted a bearer token it could never take back:**

```python
# kernel/identity/auth_utils.py (deleted)
def create_access_token(*, user_id, role, department_id) -> tuple[str, int]:
    payload = {"sub": user_id, "role": role, "type": "access",
               "exp": datetime.now(timezone.utc) + timedelta(minutes=minutes)}
    return jwt.encode(payload, os.environ["JWT_SECRET"], algorithm="HS256"), minutes * 60
```

**2.0 stores a hash of a random token and hands the plaintext to a cookie:**

```python
# kernel/identity/session.py
token = secrets.token_urlsafe(32)                 # only ever in the cookie
await tx.conn.execute(text(
    "INSERT INTO session (token_hash, realm, user_id, customer_id, expires_at, ip, user_agent)"
    " VALUES (:h, :realm, :uid, :cid, now() + :ttl, cast(:ip as inet), :ua) RETURNING id"),
    {"h": hashlib.sha256(token.encode()).digest(), ...})
```

**v1 handed the verified email to a third party's endpoint:**

```python
# kernel/identity/auth.py (deleted)
resp = await client.get("https://demobackend.emergentagent.com/auth/v1/env/oauth/session-data",
                        headers={"X-Session-ID": session_id})

**2.0 verifies the `id_token` itself and enforces the domain claim, not the request hint:**

```python
# kernel/identity/google.py

### Verified

Google sign-in start → callback with a stubbed `GoogleOidc` produces a session, binds `google_sub` and `last_login_at` on first use, redirects to a validated `next`, and refuses an unknown email (`403 NOT_PROVISIONED`), a foreign `hd`, an unverified email, a mismatched `state` and a missing `hf_oauth` cookie. `next` is forced to `/` for `//evil`, `https://evil`, `\/evil` and every other non-relative form. Dev-login gives a seeded staff user a session whose `role_ids` and `project_ids` come from `user_role_assignment` and `project_team_assignment` effective today. A customer with an active booking requests a code, reads it through `/auth/dev-otp`, verifies it and lands on a `realm=customer` session scoped to their own project; an unknown phone gets the same 200 and no `otp_challenge` row; a wrong code increments `attempts` **and commits** the increment; five wrong codes then return `423 LOCKED`; an expired code and a consumed code are both refused; a fourth request in ten minutes and a twenty-first from one IP in an hour are both `429`. The stored `code_hash` equals `sha256(code‖SESSION_SECRET)` and never contains the code. Logout revokes the row and the cookie stops working. Deactivation revokes every live session in the same transaction and blocks a fresh sign-in. `caplog` at DEBUG never contains the session token. An anonymous transaction reaches SQL with `app.realm = 'none'` and reads zero rows from `project`, `unit`, `booking`, `booking_applicant`, `unit_progress_state`. The customer realm is denied `crm_rm`, `accounts`, `project_site`, `management`, `admin` and `files` by the matrix, and sees only its own project through RLS. `require_role_in` returns `WRITE_FENCE`. Dev routes 404 when `HOMEFLOW_DEV_LOGIN` is off. All 30 v1 routers still import and mount (210 OpenAPI paths).

### Not verified / known gaps

- **Real Google is never called.** `exchange()` (the token POST and the JWKS fetch) has no test; everything from `check_claims` inwards does. A dev OAuth client is needed for the first end-to-end run.
- **Per-IP OTP rate limiting is in-process.** `otp_challenge` has no `ip` column, so a second API task would have its own counter. Marked `# ponytail:` with the upgrade path.
- **`project_team_assignment` has no team-membership table yet**, so `project_ids` comes from `primary_owner_id` / `backup_owner_id` / `escalation_manager_id` only. "Member of an assigned team" (03 §4) arrives with Policy Studio (Shared 7).
- `mypy --strict` has not been run over `kernel/` (the v1 files under it will not pass; that is the previous session's known gap and is unchanged).
- No sign-in **screen** — that is TASKS Vivek 8.
- `permission.changed`, `user.provisioned` and `user.deactivated` are catalogued but not yet emitted: the admin module that provisions users is Shared 7.

### Deviations and why

1. **`auth_scope.py` was not deleted.** The brief allows deleting it "only where the replacement is in place". RLS replaces it for Postgres tables; the v1 routers still query **Mongo**, where RLS does not exist, so removing `scope_filter_direct` / `scoped_booking_ids` / `require_*_access` would silently widen every v1 list under `HOMEFLOW_V1_MONGO=1`. It goes router by router as each is ported. The shim in `auth_utils.py` feeds it the same dict shape it always got, including a top-level `is_super_admin` so an all-projects principal is not scoped to an empty list.
2. **`hash_password` / `verify_password` were removed rather than kept**, which meant editing two v1 callers (`modules/admin/master.py` user create/update, `seeds/seed.py`). Users are provisioned without credentials now, so a password column has nothing to authenticate. v1's generated `test_credentials.md` was rewritten to describe the cookie flow instead of advertising `POST /api/auth/login`, which no longer exists.
3. **`role` seeds 13 ids, not v1's 11.** v1's `CANONICAL_ROLES` minus `customer` (a staff table), plus `qa`, `design` and `procurement` which technical 02 §4.1 names but v1 never had. The three new ones seed with `none` everywhere and get their rows in Policy Studio.
4. **New-world module levels are derived from v1's modules**, not invented: `DERIVED_MODULES` in `seeds/config/roles.py` maps each `modules/<role>/` folder and each kernel surface (`actions`, `files`, `events`) to the v1 modules whose level it inherits, highest wins. `legal` appears in both lists; the derived definition wins because `modules/legal/` covers v1's legal + documents + registrations.
5. **`/auth/*` and `/me/session` are mounted twice** — bare and under `/api/v1`. 03 writes them bare; 07 §1 puts the API under `/api/v1`. Mounting both costs one line and lets the SPA use one base URL.
6. **`load_principal()` runs on a SYSTEM transaction.** `project_team_assignment` has RLS, and it is the table that decides `app.project_ids` — a chicken-and-egg the spec does not address. The alternative was a policy that self-references the user id, which needs a migration. Scoped to that one lookup and documented in the docstring.
7. **OTP verification returns instead of raising.** A wrong code has to *commit* its attempt counter; raising inside `tx()` rolled the increment back, so the lockout never armed. `otp.consume()` returns `(customer_id, error_code)` and the router raises after the transaction closes. This was caught by a test, not by review.
8. **Booking statuses for OTP eligibility are `active` and `crm_accepted` only.** 03 §2 also lists `registered` and `handed_over`; the `booking.status` CHECK in migration 0002 has no such values yet.
9. **CSRF exempts `HEAD` and `OPTIONS` as well as `GET`** — the same safe-method set, not a wider list. `/auth/google/callback` needs no exemption: it is a GET.

## Item B — Events and jobs (TASKS Vivek 6 · technical 04)

### Why

Foundation `event-log.md` makes the event log the audit record: append-only, project-partitioned, and the thing every consumer reads. Technical 04 §1 puts the event row and the jobs its consumers enqueue in **one transaction**, so nothing is emitted without being recorded and nothing recorded is lost — no SQS, no bus, no worker service (architecture §2.3). v1's `write_audit()` wrote to a Mongo collection inside `try: … except: pass`, so an audit could silently not happen, and it recorded `create`/`update`/`delete` rather than what the business actually did.

### Benefit

Every consequential change now leaves a row that cannot be edited or deleted by the application role, carrying who, when, why, and the state either side. A whole handshake reconstructs from one `correlation_id` — `GET /events/{id}/trace` is the workflow, in order. Background work (gate re-evaluation, notifications, forecast snapshots) has somewhere to go that is transactional with the change that caused it: a rolled-back booking edit cannot leave a customer notification queued. Fifty progress updates on one villa collapse into one gate re-evaluation instead of fifty. And a job that keeps failing stops quietly retrying forever — it dies with its error recorded and emits `job.dead`, which the ops notification will hang off.

### Code difference

**v1 swallowed audit failures by design:**

```python
# kernel/mongo.py (removed)
    try:
        await db.audit_logs.insert_one({... "action": action, "before": …, "after": …})
    except Exception:
        # Auditing must never break the primary write path.
        pass
```

**2.0 appends inside the caller's transaction and lets a failure fail:**

```python
# kernel/events/legacy.py
async with tx(SYSTEM) as t:
    await append(t, "legacy.audit", subject=subject,
                 payload={"action": action, "entity_type": entity_type},
                 previous_state=_clean(before), new_state=_clean(after),
                 source={"system": "homeflow-v1", "source_record_id": entity_id})
```

**The fan-out is not a second write path — it is three lines inside `append`:**

```python
# kernel/events/append.py
for consumer in CONSUMERS.get(type, ()):
    await enqueue(tx, consumer.kind, consumer.args(subject, payload or {}),
                  dedupe_key=consumer.dedupe(subject), correlation_id=correlation,
                  project_id=project_id)
```

**And `project_id` is derived, never asked for:**

```python
async def derive_project_id(tx, subject):

            found = await tx.conn.scalar(text(f"SELECT project_id FROM {table} WHERE id = :id"), …)

The six guarantees of 04 §7 hold as integration tests: a rollback leaves neither event nor job; the consumer job carries the event's `correlation_id` and derived `project_id` and is committed with it; `homeflow_app` gets `permission denied` on both `UPDATE event` and `DELETE FROM event`; two connections cannot both take the advisory lock; five raises make a job `dead` with `last_error` set and exactly one `job.dead` event; 50 appends on one unit leave one queued job under `gate:{unit_id}`. ### Not verified / known gaps

- **`CONSUMERS` is empty at runtime.** Every entry in 04 §2 names a job kind whose handler belongs to a later slice, so all of them are commented out with their exact code; `test_every_consumer_names_a_registered_handler` guards the map, and guarantees 2 and 6 use a test-local consumer. Uncommenting is one line per slice.
- **`payload_model` is `None` on every catalogue entry.** Marked `# ponytail:` — `append()` is ready to validate through it; the typed body arrives with the slice that first emits the event.
- **`job.dead` has no `notify.send` consumer** (04 §3) because the notification outbox is TASKS Amarsh 5. The event is emitted and the line is waiting in `consumers.py`.
- **The ticker's own loop is not tested** — `tick()` and `run_one()` are, and the loop is exercised only by the running stack. The advisory-lock test uses a private lock id because the compose ticker legitimately holds 7001.
- v1's 141 `write_audit()` call sites all land as `legacy.audit`; none is yet a real business event. That happens per router as it is ported.
- Nine of the eleven schedule kinds in 04 §4 (`sla.tick`, `freshness.scan`, `hold.expire`, …) have no handler and are therefore not seeded.

### Deviations and why

1. **v1 audit actions map to `legacy.audit`, all of them.** The brief says map "where the mapping is obvious"; a grep of all 141 call sites returns exactly three action names — `create` (30), `update` (99), `delete` (12) — none of which identifies a business event. Guessing would put fiction in the audit log.
2. **`Tx` gained a `correlation_id` field.** 04 §1 reads `tx.correlation_id`; the previous session's `Tx` had only `conn` and `principal`. Defaulted to `None`, so every existing call site is unchanged.
3. **`kernel/mongo.py` re-exports `write_audit`.** Moving the function to `kernel/events/legacy.py` while keeping `from kernel.mongo import get_db, write_audit` working in 30 routers was a two-line re-export instead of 30 edited imports.
4. **Intervals are passed as `timedelta`, never as strings.** asyncpg binds a parameter before the cast, so `cast(:ttl as interval)` with `"7 days"` fails with `'str' object has no attribute 'days'`. Every interval parameter in identity, jobs and files is a `timedelta`. Three separate bugs came from this; it is worth knowing.
5. **The events router uses `Annotated[Principal, Depends(require(...))]` at module level** rather than `Depends(...)` in a default, because ruff's `B008` is on. That is now the shape every 2.0 router should copy.
6. **The ticker commits explicitly rather than using `conn.begin()`.** SQLAlchemy's async connection autobegins on the advisory-lock query, so a nested `begin()` raises. Getting this wrong killed the ticker on its first pass and left `/health` reporting `holder: false` — the health field earned its place immediately.

## Item C — Files (TASKS Vivek 7 · technical 08 §1)

### Why

Technical 08 §1 is explicit that **the API never proxies bytes**: the browser PUTs to S3 and GETs from S3 through presigned URLs, and Postgres holds only `file_object` metadata. v1 streamed every upload through FastAPI into GridFS (or the container filesystem) and streamed every download back out, which puts the API process on the critical path for a 50 MB drawing, ties file storage to Mongo, and makes an ECS task's memory the upload limit. One path — presign → PUT → confirm → 302 — now serves drawings, snag photos, QA evidence, handover packs and generated documents alike.

### What changed

| Path | What |
|---|---|
| `services/api/kernel/files/port.py` | **new** — the `Files` port, `FileMeta` / `PresignedUpload`, the allowed content-type list, 50 MB cap, TTLs, `s3()` vs `signer()`, `s3_key()` |
| `services/api/kernel/files/ownership.py` | **new** — `entity_type` → owning module + parent table + whether it may be customer-facing; unlisted types are refused |
| `services/api/kernel/files/service.py` | **new** — `presign_upload` (validate → RLS read of the parent → `file_object(status='pending')` → presigned PUT), `confirm` (HEAD, size, inline sha256 ≤ 5 MB else a job, `status='ready'`, `file.attached`), `download_url` (visibility check → presigned GET) |
| `services/api/kernel/files/router.py` | **new** — `POST /api/v1/files/presign`, `POST /api/v1/files/{id}/confirm`, `GET /api/v1/files/{id}` → 302 |
| `services/api/kernel/files/handlers.py` | **new** — `file.checksum` (out-of-band sha256) and `file.prune` (pending > 24 h + its orphan object) |
| `services/api/kernel/files/attachments.py`, `storage.py` | **deprecated in code** with the replacement path named |
| `services/api/migrations/versions/0001_kernel.py` | `GRANT DELETE ON … file_object` — `file.prune` needs it |
| `services/api/migrations/versions/0003_twins.py` | customer policy on `file_object` (`customer_facing` + own project) |
| `services/api/seeds/config/schedules.py` | `file.prune` daily at 04:30 |
| `services/api/settings.py`, `.env.example` | `S3_PUBLIC_ENDPOINT_URL` |
| `services/api/tests/security/test_files.py` | **new** — 11 tests against real MinIO |

### Benefit

A 50 MB drawing goes browser → MinIO/S3 without touching a Python process, so upload throughput stops being an API scaling problem and an ECS task cannot be exhausted by concurrent uploads. Every file carries a derived `project_id`, so RLS scopes it like any other row: a staff member on another project cannot even see it exists. A customer can only ever be handed a file explicitly marked `customer_facing`, and asking for an internal one returns 404, not 403 — no existence leak. Every stored file has a sha256, so a document's bytes can be proved unchanged years later, which is exactly what the execution record in 08 §2 will need. Abandoned uploads clean themselves up daily instead of accumulating orphan objects nobody knows about.

### Verified

presign → PUT (real boto3 signature, real MinIO) → confirm → `GET` 302 → fetch returns the exact bytes, with the `file_object` row at `s3_key = {project_id}/snag/{snag_id}/{file_id}`, the object present in the bucket at that key, `sha256` matching `sha256sum` of the file on disk, and exactly one `file.attached` event carrying the subject. A content type off the list, a size over 50 MB and an unknown `entity_type` are each 400 with the offending field named. A parent row the caller cannot see is 404. `customer_facing` on an internal-only entity (`unit`) is refused. An internal file is invisible to the customer realm and becomes reachable the moment `visibility` flips. A `file_object` row is invisible to a staff principal on another project. A file over 5 MB returns `sha256: null`, queues exactly one deduped `file.checksum` job, and the handler fills in the digest that matches. `file.prune` removes a `pending` row older than a day **and** its orphan object from MinIO. The presigned URL is signed against the browser-reachable host and carries `X-Amz-Signature`. On a stack rebuilt from empty volumes, `file.prune` runs to `done` on its schedule.

### Not verified / known gaps

- **The customer policy on `file_object` is project-scoped, not entity-scoped.** A customer could see a `customer_facing` file attached to another buyer's snag *in the same project*. Marked `# ponytail:` in migration 0003 with the upgrade path: the customer-portal slice (TASKS Vivek 15) owns what a customer may see and should narrow this to their own unit/booking rows. The service-layer visibility check is the second gate today.
- **No multipart upload.** A single presigned PUT caps at the 50 MB limit, which is the spec's limit; multipart is the change if that limit rises.
- **Bucket versioning, SSE-S3 and the 90-day IA lifecycle rule** (08 §1) are CDK, not compose — TASKS Vivek 9.
- `Idempotency-Key` is not wired to `POST /files/presign` yet; the kernel dependency exists but no route uses it.
- The DWG content types are guesses at what the site team's CAD exports send (`image/vnd.dwg`, `application/acad`); confirm against a real upload.

### Deviations and why

1. **v1's attachment routes were *not* re-pointed at S3.** The brief allows "mark them deprecated and record it as a deviation" when it is not a small change, and it is not: v1 attachments have string ids, their own `attachments` collection, a verification workflow, comment linkage and category rules with no counterpart in `file_object`. Re-pointing them is the Mongo → Postgres cutover (TASKS Vivek 16). Both files now carry a DEPRECATED banner naming the replacement.
2. **`aiofiles` stays in `pyproject.toml`.** Seven v1 modules import it (`payments`, `tds`, `communications`, `legal`, `registrations`, `document_generation`, `attachments`), not just the attachment router. It goes with those routers.
3. **`GRANT DELETE ON file_object` was added by amending migration 0001** rather than writing a new one. 08 §1 requires `file.prune` to delete pending rows, which 02 §1's grant list does not allow. A new migration would have to be `0004`, which TASKS assigns to Amarsh (`0004_action_journey`); migrations 0001–0003 are uncommitted work from the previous session in the same unreleased branch. `downgrade base` → `upgrade head` was re-run clean, and the stack was rebuilt from empty volumes to prove it.
4. **The customer policy on `file_object` lives in 0003, not 0001**, for the same reason 0002's customer policies do: `booking_applicant` does not exist when `file_object` is created.
5. **Presigned URLs are signed against the public endpoint, not rewritten afterwards.** 08 §1 says "the presigned URL host is rewritten to `localhost:9000`". SigV4 signs the Host header, so a post-hoc rewrite produces a URL MinIO answers with 403 — which is exactly what the first hand-run did. `signer()` builds a client on `S3_PUBLIC_ENDPOINT_URL` for minting URLs while `s3()` keeps `S3_ENDPOINT_URL` for the API's own HEAD/GET/DELETE. In AWS `S3_PUBLIC_ENDPOINT_URL` is unset and the two are identical.
6. **`GET /files/{id}` does not use `require()`.** A customer realm has no staff matrix row, and the route must serve both realms; it checks `files:read` for staff and leans on RLS + `visibility` for customers, which is what 08 §1 describes.
7. **`file.prune` was seeded as a schedule in Item B**, one item before its handler existed. It failed once with `no handler registered`, retried after the backoff, and has run clean since Item C registered the handler — an accidental but honest demonstration of the retry path.

### Files

```bash
# 1. presign (entity must exist and be visible; snag/unit/booking/customer/project/… )
RESP=$(curl -s -X POST -b /tmp/hf.txt -H "X-Requested-With: HomeFlow" \
  -H "Content-Type: application/json" \
  -d '{"entity_type":"snag","entity_id":"<snag-uuid>","filename":"snag-before.pdf",
       "content_type":"application/pdf","size_bytes":29}' \
  http://localhost:8001/api/v1/files/presign)
FILE_ID=$(echo "$RESP" | python -c "import sys,json;print(json.load(sys.stdin)['data']['file_id'])")
URL=$(echo "$RESP" | python -c "import sys,json;print(json.load(sys.stdin)['data']['upload']['url'])")

# 2. the browser PUTs straight to MinIO
curl -X PUT -H "Content-Type: application/pdf" --data-binary @/tmp/evidence.pdf "$URL"

# 3. confirm — records size + sha256, marks ready, emits file.attached
curl -s -X POST -b /tmp/hf.txt -H "X-Requested-With: HomeFlow" \
  "http://localhost:8001/api/v1/files/$FILE_ID/confirm"

# 4. download — 302 to a 5-minute presigned GET
curl -sL -b /tmp/hf.txt "http://localhost:8001/api/v1/files/$FILE_ID"
```
